# SmartWardrobe — статус проекта (этап «Недели 3–5. Базовая реализация»)

## 1. Краткое описание проекта

**SmartWardrobe** — приложение, которое позволяет вести личный гардероб: добавлять
вещи (с фотографией), распределять их по категориям, собирать образы из вещей,
отмечать использование и получать аналитику по тому, какие вещи носятся редко.

Приложение состоит из четырёх модулей:

| Модуль | Назначение |
|---|---|
| **Гардероб** | Список вещей, добавление (фото/описание/цена), просмотр, редактирование, удаление, фильтр по категориям |
| **Образы** | Создание образов из вещей, редактирование состава, удаление, отметка «Надеть сегодня» |
| **Аналитика** | Статистика и список вещей, которые давно не носили |
| **Профиль** | Данные пользователя, безопасность |

## 3. Что реализовано на текущий момент

### 3.1. Гардероб (полностью)
- Сетка вещей (2 колонки), фильтр по категориям: Все / Верх / Низ / Обувь / Верхняя одежда / Аксессуары.
- Карточка вещи: название, категория, описание, цвет, фото.
- **Добавление вещи**: фото (камера/галерея), описание, название, стоимость, категория, цвет, сезон.
- **Просмотр вещи** (отдельный экран).
- **Редактирование** всех данных + **перефотографирование**.
- **Удаление** вещи (с подтверждением, вместе с файлом фото).
- Пустой гардероб по умолчанию.

### 3.2. Образы (полностью)
- Создание образа из вещей (вещи сгруппированы по категориям).
- Список образов с превью вещей.
- **Редактирование**: название, добавление/удаление/замена вещей.
- **Удаление** образа.
- **«Надеть сегодня»** — одно нажатие отмечает дату и счётчик у всех вещей образа.
- Логика целостности: при удалении вещи она убирается из образов; если образ опустел — удаляется сам образ.

### 3.3. Аналитика (на реальных данных)
- Список «Реже всего носились» — сортировка по дате последнего использования.
- Карточки: всего вещей, ни разу не надевали, процент неиспользуемых.
- Для каждой вещи: дата последнего использования («ни разу» / дата) и количество использований.

### 3.4. Профиль (базовая структура)
- Экран с данными пользователя, предпочтениями и блоком безопасности.
- Таблица `users` в БД заложена (подключение профиля к БД — следующий шаг).

## 4. Архитектура и структура проекта

```
lib/
├── main.dart                  ← точка входа: инициализация БД, тема, запуск
├── models/
│   ├── clothing_item.dart     ← модель «Вещь»
│   └── outfit.dart            ← модель «Образ»
├── screens/
│   ├── home_screen.dart       ← нижнее меню (4 вкладки)
│   ├── wardrobe_screen.dart   ← Гардероб
│   ├── add_item_screen.dart   ← добавление/редактирование вещи
│   ├── item_detail_screen.dart← просмотр вещи
│   ├── outfits_screen.dart    ← Образы
│   ├── create_outfit_screen.dart ← создание/редактирование образа
│   ├── analytics_screen.dart  ← Аналитика
│   └── profile_screen.dart    ← Профиль
├── services/
│   ├── database_service.dart  ← SQLite: схема, CRUD, маппинг
│   ├── app_paths.dart         ← пути приложения, относительный/абсолютный путь
│   ├── image_service.dart     ← сохранение/удаление файлов фото
│   ├── wardrobe_store.dart    ← состояние вещей (ValueNotifier) + запись в БД
│   └── outfit_store.dart      ← состояние образов + логика использования
├── widgets/
│   └── clothing_card.dart     ← карточка вещи (переиспользуемая)
└── utils/
    ├── app_colors.dart        ← сопоставление названий цветов
    └── formatters.dart        ← форматирование денег и дат
```

**Принцип:** чёткое разделение слоёв — модели данных, экраны, логика/хранилище, UI-виджеты, утилиты.

## 5. База данных (SQLite)

Схема хранится в папке `sqlite/` (`schema.sql`, `seed.sql`, `README.md`, `database.db`).

**Сущности:** `users`, `categories`, `colors`, `seasons`, `clothing_items`,
`item_seasons`, `outfits`, `outfit_items`, `wear_log`, `wear_log_items`.

**Связи:**
- `users 1 → * clothing_items`, `users 1 → * outfits`;
- `clothing_items * ↔ * seasons` (через `item_seasons`);
- `outfits * ↔ * clothing_items` (через `outfit_items`);
- `wear_log * ↔ * clothing_items` (через `wear_log_items`).

**Правила удаления:** `ON DELETE CASCADE` для связей (удаление вещи убирает её из
образов, удаление образа чистит состав), `RESTRICT` для категорий, `SET NULL` для цветов.

**Хранение фото:** файлы лежат в папке приложения (`app_flutter/images/`),
в БД хранится только **относительный путь** к файлу. При удалении вещи удаляется и файл.
