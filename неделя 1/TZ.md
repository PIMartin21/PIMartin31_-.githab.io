**Сильные стороны приложений:**

Acloset: автоматическое распознавание вещей по фото (через ИИ), удобная статистика использования гардероба, синхронизация между устройствами.

Fits: качественный подбор образов под погоду, приятный минималистичный дизайн, интеграция с магазинами одежды.

**Основные недостатки приложений:**

3. Долгая загрузка изображений. 

4. После обновления приложения сбрасывается ранее сохраненный гардероб.

5. Нет информации о доступных функциях приложения без подписки.

6. Трудности с покупкой подписки у пользователей, которые не могут оплатить ее через платежную систему google play.

**Анализ целевой аудитории**

Целевая аудитория: люди в возрасте от 18 до 50 лет,  ведущие активный образ жизни, которые хотят быстро собирать образы, не тратить время утром перед зеркалом и контролировать свой гардероб.

Пользователям важна скорость работы приложения, удобство интерфейса, возможность полностью оценить функционал приложения без покупки подписки и удобство в оплате дополнительных функций.

7. **Разработка плана тестирования**

7.1 **Тестовые сценарии:**

**Тест 1. Добавление вещи**

1.1. Открыть приложение.

1.2. Нажать кнопку «+» на экране «Гардероб».

1.3. Выбрать фото из галереи.

1.4. Ввести название вещи.

1.5. Выбрать категорию (верх, низ, обувь, аксессуары).

1.6. Нажать «Сохранить».

**Ожидаемый результат:** вещь появляется в списке гардероба.

**Тест 2. Подбор образа по погоде**

2.1. Перейти на экран «Образы».

2.2. Нажать «Подобрать по погоде».

2.3. Разрешить доступ к геолокации.

2.4. Дождаться загрузки рекомендации.

**Ожидаемый результат:** система отображает подобранный образ из 1 вещи верх + 1 низ + обувь, отфильтрованных по текущей температуре».

**Тест 3. Редактирование вещи**

3.1. Открыть экран «Гардероб».

3.2. Нажать на существующую вещь.

3.3. Нажать кнопку «Редактировать».

3.4. Изменить название или категорию.

3.5. Нажать «Сохранить».

**Ожидаемый результат**: данные о вещи обновляются.

**Тест 4. Удаление вещи**

4.1. Открыть экран «Гардероб».

4.2. Нажать на существующую вещь.

4.3. Нажать кнопку «Удалить».

4.4. Подтвердить удаление в диалоговом окне.

**Ожидаемый результат:** вещь исчезает из списка гардероба.

**Тест 5. Офлайн-режим**

5.1. Отключить интернет на устройстве.

5.2. Открыть приложение.

5.3. Перейти в «Гардероб».

**Ожидаемый результат:** ранее добавленные вещи отображаются.

5.4. Добавить новую вещь.

**Ожидаемый результат:** вещь сохраняется локально.

5.5. Перейти в «Образы» и нажать «подобрать по погоде».

**Ожидаемый результат:** сообщение «Требуется интернет для получения погоды» ИЛИ используется кэшированная погода.

**Тест 6. Просмотр статистики**

6.1. Открыть экран «Аналитика».

6.2. Проверить отображение «Топ-3 часто используемых вещей».

6.3. Проверить отображение «Список забытых вещей» (не использовались более 30 дней).

**Ожидаемый результат**: оба списка отображаются корректно; при отсутствии данных показывается пустое состояние».

**Тест 7. Сохранение образа**

7.1. На экране «Образы» собрать образ вручную или сгенерировать по погоде.

7.2. Нажать кнопку «Сохранить образ».

7.3. Ввести название образа.

7.4. Нажать «Сохранить».

**Ожидаемый результат:** образ появляется в списке «Сохранённые образы».

**Тест 8. Переключение темы (светлая/тёмная)**

8.1. Открыть экран «Профиль» → «Настройки».

8.2. Выбрать «Тёмная тема».

**Ожидаемый результат:** интерфейс меняет цвета на тёмные.

8.3. Выбрать «Светлая тема».

**Ожидаемый результат**: интерфейс возвращается к светлым цветам.

7.2 **Критерии приёмки:**

Приложение запускается без ошибок.

Пользователь может добавить 3 разные вещи и увидеть их в списке.

При выборе «Подобрать по погоде» система отображает рекомендацию

  из 1 вещи верх + 1 низ + обувь, отфильтрованных по температуре.

Приложение работает без интернета (кроме погоды).

**8. ОЦЕНКА РИСКОВ И ОГРАНИЧЕНИЙ**

8.1.** Анализ основных рисков**

Первый и самый серьёзный риск – потеря данных пользователя при обновлении приложения. Если после обновления через Google Play или App Store у пользователя исчезнет весь гардероб, доверие к приложению будет потеряно, и пользователь его удалит. Вероятность этого риска средняя, но серьёзность последствий высокая.

Второй риск — недоступность API погоды OpenWeatherMap. Если сервис перестанет работать или изменит тарифы, приложение не сможет давать рекомендации по погоде, что является одной из ключевых функций. Вероятность низкая, но серьёзность высокая.

Третий риск – проблемы совместимости с разными версиями операционных систем. Приложение может работать на одних устройствах и вылетать на других. Это приведёт к негативным отзывам и низкой оценке преподавателя. Вероятность средняя, серьёзность высокая.


**8.2 Планирование управления рисками**

Для предотвращения потери данных в требованиях к системе (пункт 5.3) предусмотрено еженедельное локальное резервное копирование и автоматическое сохранение состояния при закрытии приложения. 

Для минимизации риска недоступности API погоды реализуется кэширование последних полученных данных на 24 часа. При отсутствии интернета или сбое API приложение будет использовать кэшированные данные с уведомлением пользователя.

Для минимизации риска проблем совместимости тестирование будет проводиться на эмуляторах с Android 10–14 и iOS 14–17, а также на реальных устройствах, если они доступны. Выбор Flutter также снижает этот риск, так как фреймворк обеспечивает высокую совместимость.
